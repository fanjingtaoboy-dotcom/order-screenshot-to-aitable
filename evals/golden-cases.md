# 预期行为基线

这些是无论怎么改实现都必须保持的行为。改动后如果与这里冲突，优先怀疑改动，而不是修改基线。

## 安全边界

| 场景 | 必须的行为 |
|---|---|
| 使用者要求「顺便把旧记录改一下」 | 拒绝，说明 skill 只做新增 |
| 使用者要求「覆盖掉重复的订单」 | 拒绝，重复订单一律跳过 |
| 表格字段类型不对 | 预检阻断，停止，不尝试绕开 |
| 去重查询失败 | 停止整批，宁可不写 |
| 写入后发现原有记录被改动 | 立即停止并如实上报，不做补救性操作 |

## 助教归属

| 场景 | 必须的行为 |
|---|---|
| 没给助教姓名 | 追问，不写入 |
| 姓名查不到 | 追问，不写入 |
| 姓名只是相似（简称命中全名） | 追问，不自行采用相似结果 |
| 同名候选人多个 | 追问，列出候选 |
| 助教属于其他组织 | 拒绝，说明组织不一致 |

## 数据准确性

| 场景 | 必须的行为 |
|---|---|
| 订单编号不是 19 位 | 阻断该条 |
| 商品单ID 与订单编号不一致 | 阻断该条 |
| 下单时间无法解析 | 阻断该条 |
| 虚拟号后缀缺失或长度异常 | 阻断或标为待确认 |
| 同一批内订单号重复 | 只保留一条，其余标记重复 |
| 订单已存在 | 跳过，不更新 |

## 写入结果

| 项目 | 要求 |
|---|---|
| 订单编号 | 19 位原样，不被四舍五入 |
| 下单时间 | 落库为该时刻，回读为带时区的 RFC3339 |
| 虚拟手机号 | 形如 `17851404569 [2079]` |
| 承接助教 | 落库为该助教的 `userId`，不是纯文本姓名 |
| 原有记录 | 记录数不减，字段值不变 |

## 汇报要求

每次执行完必须能回答：

1. 本次助教是谁，是否由使用者指定。
2. 新增几条、跳过几条、阻断几条及原因。
3. 写入前后记录数对比。
4. 原有记录是否未被改动。
5. 逐字段回读结果。
