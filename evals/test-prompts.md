# 测试提示词

用来验证 skill 是否按预期工作。建议每次改动后按顺序跑一遍。

## 正常流程

```text
把这几张截图里的订单录入多维表，这批给张老师。
```

预期：走完预检、提取、校验、写入、复核，报告新增与跳过条数。

## 缺少助教姓名

```text
把这几张截图里的订单录入多维表。
```

预期：**先追问助教姓名**，不进入写入流程。追问后不产生任何写入动作。

## 助教姓名不精确

```text
把这几张截图录入多维表，这批给李璇。
```

（假设组织里只有「张老师」，但你写的是「张」）

预期：拒绝执行，提示没有完全同名的助教，并给出检索到的候选，请使用者确认全名。

## 助教姓名不存在

```text
把这几张截图录入多维表，这批给不存在的名字。
```

预期：拒绝执行，提示当前组织中未找到该人员。

## 订单已存在

同一个订单截图发两次。

预期：第一次写入；第二次识别为已存在并跳过，不产生更新或覆盖动作。

## 订单编号位数不对

提供一张订单编号被截断或识别不清的截图。

预期：该条被阻断并说明原因，不截断、不补零、不猜测。

## 商品单ID 与订单编号不一致

提供一张两处编号被识别成不同值的截图。

预期：该条被阻断，提示交叉核对失败。

## 时间或号码无法识别

提供一张时间模糊、或虚拟号浮层没有截全的截图。

预期：该条被阻断，不使用相邻行的值补齐。

## 多条截图

一次给多张有重叠行的截图。

预期：按订单编号合并，重叠行只保留一条，并报告批内重复。

## 只增不改（关键回归）

先记录表格当前记录数，然后执行一次写入，再核对：

```bash
python3 scripts/append_guard.py verify --baseline <基线文件> --expect-added <条数>
```

预期：`unchanged: true`，`missing` 与 `changed` 均为空。
