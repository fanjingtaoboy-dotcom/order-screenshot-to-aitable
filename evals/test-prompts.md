# 测试提示词

用来验证 skill 是否按预期工作。建议每次改动后按顺序跑一遍。

## 正常流程

```text
把这几张截图里的订单录入多维表，这批给张老师。
```

预期：走完预检、提取、校验、写入、复核，报告新增与跳过条数。

## 只给截图、没提助教

```text
把这几张截图里的订单录入多维表。
```

预期：正常执行，不追问助教，不产生任何与人员相关的接口调用。

## 使用者主动提到助教

```text
把这几张截图录入多维表，这批给张老师。
```

预期：说明本 skill 不填助教这一列，按三列正常写入，助教列留空。

## 单条订单带备注

```text
把这张截图录入多维表。订单 6929387397478383133 备注：客户要求改地址。
```

预期：该订单写入四列，备注落在「订单备注」列。

## 多条订单，备注指明了订单号

```text
这几张截图录入多维表。6929383139720723655 备注：工作日送。
```

预期：只有该订单带备注，其它订单不写备注列。

## 多条订单，备注没说哪一单

```text
这几张截图录入多维表，客户要求加急发货。
```

预期：**停下追问**是哪一单，不写入，不随意套用。

## 备注指定的订单号不在本次截图里

预期：停下并提示核对订单编号。

## 已存在的订单带备注

预期：整条跳过，备注也不写入，并说明不覆盖已有记录。

## 订单已存在

同一个订单截图发两次。

预期：第一次写入；第二次识别为已存在并跳过，不产生更新或覆盖动作。

## 订单编号位数不对

提供一张订单编号被截断或识别不清的截图。

预期：该条被阻断并说明原因，不截断、不补零、不猜测。

## 商品单ID 与订单编号不一致

提供一张两处编号被识别成不同值的截图。

预期：该条被阻断，提示交叉核对失败。

## 时间或号码无法识别

提供一张时间模糊、或虚拟号浮层没有截全的截图。

预期：该条被阻断，不使用相邻行的值补齐。

## 多条截图

一次给多张有重叠行的截图。

预期：按订单编号合并，重叠行只保留一条，并报告批内重复。

## 只增不改（关键回归）

先记录表格当前记录数，然后执行一次写入，再核对：

```bash
python3 scripts/append_guard.py verify --baseline <基线文件> --expect-added <条数>
```

预期：`unchanged: true`，`missing` 与 `changed` 均为空。
