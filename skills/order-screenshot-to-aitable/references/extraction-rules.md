# 截图提取规则

## 数据来源

抖店后台「订单管理」列表页截图。列表默认按下单时间倒序，每条订单一行。

一次可以给多张截图：同一页的多屏滚动、不同时间段、或者不同页。把它们合并成**一个** JSON 文件再进校验。

多张截图合并时：

- 以订单编号为唯一键，重复出现的订单只保留一条。
- 不同截图里字段冲突（例如同一订单两个不同号码）时不要自行取舍，把冲突写进报告交给使用者确认。
- 相邻截图可能有重叠行，重叠不算错误，交给校验脚本按批内重复识别。
- 每张截图各自完整取值，不要跨截图拼接一条订单的字段。

页面上的关键信息分三处，必须全部取到才算一条完整记录：

| 信息 | 位置 | 备注 |
|---|---|---|
| 订单编号 | 行首标题栏 | 19 位数字，页面上可能带千分位或图标 |
| 下单时间 | 行首标题栏 | 完整到秒 |
| 商品单ID | 商品信息区底部 | 与订单编号相同，用作交叉校验 |
| 虚拟号后缀 | 右侧「虚拟号」前的方括号 | 默认被隐藏，需先点闭眼图标 |
| 完整号码 | 悬停虚拟号后弹出的浮层 | 浮层内「收货信息」一行 |
| 收货人 | 同一浮层 | 姓名，写入时随记录留存备查 |

## 取值步骤

1. 读取行首的订单编号与下单时间。
2. 记录同一行的商品单ID。
3. 点击该行右侧「虚拟号」前的闭眼图标，使后缀数字显示出来。
4. 将鼠标悬停在「虚拟号」文字上，等待浮层出现。
5. 从浮层读取收货人姓名与完整手机号，与已显示的后缀组成一条记录。

## 输出格式

产出一个 JSON 文件，交给 `scripts/validate_records.py` 校验：

```json
{
  "records": [
    {
      "orderNo": "6917731421701746343",
      "productOrderId": "6917731421701746343",
      "orderTime": "2026-09-11 16:05:04",
      "recipientName": "杨先生",
      "phoneWithSuffix": "17851404569 [2079]"
    }
  ]
}
```

`phone` 与 `suffix` 也可分两个字段给出，脚本会自动合成。

## 硬性要求

- 订单编号必须是纯数字且为 19 位。带空格、千分位、图标时先剥离再记录。
- 绝不根据上下文推断被遮挡或看不清的数字。看不清就留空，让校验脚本把它标为阻断项。
- 商品单ID 与订单编号不一致时立即停下并回报，不要二选一。
- 同一订单在多张截图中重复出现时只保留一条，其余交给校验脚本识别为批内重复。
- 虚拟号浮层一次只显示一条订单，切忌把相邻行的号码写到别的订单上；写入前用订单编号与号码成对复核。

## 常见易错点

| 现象 | 处理 |
|---|---|
| 订单号末几位像 `...743000` | 很可能是历史数字字段四舍五入的残留，必须用页面原始值覆盖记录 |
| 浮层显示的是相邻行 | 重新悬停目标行的虚拟号，确认浮层收货人与当前订单对应 |
| 后缀只有 3 位或 5 位 | 标为待确认，不直接写入 |
| 截图只截到订单编号没有号码 | 只用于去重对照，不生成写入记录 |
